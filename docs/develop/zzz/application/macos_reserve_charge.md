# Mac 体力计划补电

在原体力计划页选择恢复来源。使用储蓄或混合来源时，通过「本日储蓄电量额度」保存当天累计上限。日期按北京时间，额度填 0 撤销。配置字段为 `macos_reserve_date` 和 `macos_reserve_limit`，支持 1 至 320 电量。仅使用以太电池时按原恢复选项授权。默认恢复「不使用」，过期额度不沿用。

当前代码覆盖普通实战模拟室、默认等级的普通区域巡防，以及燃竭关闭后的普通专业挑战室。模拟室以选中专项的实际消耗核对一至五卡，默认数量读游戏已保存的卡数。储蓄逐点补本场差额，电池按每枚 60 电量取达到本场所需的最少整枚。混合模式优先使用足以补满差额的储蓄，余额或额度不足时再检查电池。循环、双倍、培养、显式 Lv.60 巡防和深度追猎补电暂不开放。

在已核对的不足预设按一次 Start。恢复页须显示三个来源和各自余额。识别唯一焦点、所选来源的说明和黄色确认后进入快捷使用。快捷使用页须显示相同来源、持有量、准确数量及 A 确认。确认前持久化本机回执，获得后回原预设检查电量增量。随后回大世界，从快捷手册和仓库读取余额。仓库标题、菲林图标和八位金额必须同时匹配，两处电量读数须一致或只差一次自然恢复。实际扣减等于本次使用量且其他来源余额一致后，回到原任务重读预设。

本机 `.debug/macos/reserve_<实例>_<日期>.json` 记录本次来源及本日累计使用的储蓄。保存意图时按实例加锁并重新读取原始回执，跨进程或跨日遇到待核账回执立即停止。自然恢复临近、来源或数量不明、证据保存失败、扣减不符、其他来源余额变化或核账失败都停止。明确余额或额度不足时关掉弹窗，回到原电量不足与跳过计划流程。胜利次数在实际完成副本后更新。

2026-11-01 首次正式 CLI 实测从 19 补至 60，余额减少 41，电池与菲林一致。该流程使用旧五卡预设核账，之后完成最后一次巡防。
